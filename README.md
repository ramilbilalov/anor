# Anor — сайт доставки для ресторана

Сайт доставки блюд одного ресторана (аналог Яндекс.Доставки): каталог с меню,
корзина, оформление заказа с адресом доставки и админ-панель для управления меню
и просмотра заказов.

📄 **[ADMIN.md](ADMIN.md)** — подробная инструкция по админ-панели.
🚀 **[DEPLOY.md](DEPLOY.md)** — как развернуть сайт (VPS, HTTPS, бэкапы).

## Возможности

**Публичная часть**
- Каталог блюд по категориям (фото, описание, состав, цена в рублях)
- Страница блюда с подробным составом
- Информация о ресторане: адрес, телефон, часы работы, условия доставки
  (главная, подвал, страница «О ресторане»)
- Корзина (сохраняется в браузере)
- Оформление заказа: имя, телефон, адрес доставки, комментарий
- Страница подтверждения заказа
- Оплата при получении (без онлайн-оплаты)

**Админ-панель** (`/admin`)
- Вход по логину и паролю с **защитой от подбора** (блокировка после 5 неверных
  попыток на 15 минут)
- Управление меню: категории и блюда (создание, редактирование, удаление,
  загрузка фотографий, скрытие блюд)
- Список заказов с составом, контактами и адресом
- Смена статуса заказа (новый → подтверждён → готовится → в доставке → выполнен)
- Настройки: редактирование информации о ресторане

## Стек

- **Next.js 16** (App Router) + **React 19** + **TypeScript**
- **Tailwind CSS 4**
- **Prisma 7** + **SQLite** (через driver adapter `better-sqlite3`)

## Требования

- **Node.js 18+** (проект проверялся на Node 22)

  Если используете `nvm`:
  ```bash
  nvm use 22
  ```

## Запуск

1. Установить зависимости:
   ```bash
   npm install
   ```

2. Создать файл `.env` (можно скопировать из `.env.example`) и задать значения:
   ```bash
   cp .env.example .env
   ```
   Переменные:
   - `DATABASE_URL` — путь к базе SQLite (по умолчанию `file:./dev.db`)
   - `ADMIN_USERNAME` / `ADMIN_PASSWORD` — логин и пароль админ-панели
   - `SESSION_SECRET` — секрет для подписи сессионной cookie (обязательно
     смените в продакшене)
   - `NEXT_PUBLIC_RESTAURANT_NAME` — название ресторана в шапке сайта

3. Применить миграции и заполнить меню тестовыми данными:
   ```bash
   npm run db:migrate
   npm run db:seed
   ```

4. Запустить дев-сервер:
   ```bash
   npm run dev
   ```
   Сайт: http://localhost:3000
   Админка: http://localhost:3000/admin (логин/пароль из `.env`)

## Структура

```
src/
  app/
    page.tsx                 # каталог (главная)
    product/[id]/            # страница блюда
    cart/                    # корзина
    checkout/                # оформление заказа
    order/[id]/              # подтверждение заказа
    about/                   # страница «О ресторане»
    admin/
      login/                 # вход в админку
      orders/                # список заказов + смена статуса
      menu/                  # управление меню
      settings/              # информация о ресторане
    api/
      orders/                # создание заказа (публичное)
      admin/                 # login/logout, categories, products, orders, upload, settings
  components/                # Header, SiteFooter, CartProvider, кнопки
  lib/
    prisma.ts                # клиент Prisma (+ SQLite адаптер)
    auth.ts                  # сессии админа (подписанная cookie)
    rateLimit.ts             # защита логина от подбора пароля
    settings.ts              # чтение/запись информации о ресторане
    format.ts                # форматирование цен (₽) и статусов
  proxy.ts                   # защита маршрутов /admin и /api/admin
prisma/
  schema.prisma              # модели Settings, Category, Product, Order, OrderItem
  seed.ts                    # тестовые данные
public/uploads/              # загруженные фотографии блюд
```

## Примечания

- Цены хранятся целым числом (в рублях) и форматируются на лету.
- Загруженные изображения сохраняются в `public/uploads` и не попадают в git.
- В Next.js 16 middleware переименован в `proxy.ts` — он защищает
  `/admin/*` и `/api/admin/*`, пропуская только страницу входа.
- Защита от подбора пароля (`src/lib/rateLimit.ts`) — in-memory, рассчитана на
  один инстанс приложения (совпадает со сценарием SQLite).
- Для реальной эксплуатации: смените `ADMIN_PASSWORD` и `SESSION_SECRET`
  (см. [ADMIN.md](ADMIN.md)) и разворачивайте по [DEPLOY.md](DEPLOY.md).
